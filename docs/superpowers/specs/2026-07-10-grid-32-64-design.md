# Loooop/Löp Grid 32 and 64 Divisions — Design

2026-07-10

Extends the grid mode shipped by `2026-07-10-grid-mode-design.md`.

## Purpose

Add two finer divisions to the global Grid setting, on both Loooop and Löp,
both hosts: **Off / 4 / 8 / 16 / 32 / 64** (default Off, unchanged).

## What changes

The engine and display renderer are already generic over the segment count —
`LoopEngine::setGrid()` accepts any N and `windowBounds()` quantization and
the N−1 grid bars follow. This is purely a choice-list extension:

1. **Shared table** — `gridSegments()` in `src/loooop/LooperModuleDSP.hpp`:
   `{0, 4, 8, 16}` → `{0, 4, 8, 16, 32, 64}`; bounds check becomes 0–5;
   comment updated.
2. **VCV Loooop** — `configSwitch(GRID_PARAM, …)` in `src/loooop/Loooop.cpp`:
   max 3 → 5, labels gain `"32", "64"`. The panel `RoundBlackSnapKnob`
   follows the param range automatically; no SVG change (the panel has only
   the "Grid" caption, no per-position markings).
3. **VCV Löp** — same `configSwitch` change in `src/loooop/Lop.cpp` plus its
   context-menu label list (`kGridLabels`).
4. **MetaModule** — `QlpGridAlt` in `metamodule/loooop/QlpElements.hh`:
   `num_pos` 4 → 6, labels gain `"32", "64"`. The class is shared by Loooop
   and Löp, so both get the new choices together. The SDK maps stored
   normalized values by `round(val * (num_pos − 1))`, so this remaps any
   patch saved with grid set — acceptable because grid mode is unreleased
   (exists only on `loooop-track`, no tagged release contains it).

## What doesn't change

- Engine semantics, display rendering, persistence — all generic already.
- Default (Off) and param ids — existing patches load unchanged.

## Testing

- `tests/loooop/test_module_dsp.cpp`: extend the `gridSegments` checks —
  choice 4 → 32, choice 5 → 64, out-of-range is now < 0 or > 5 → 0.
- `tests/loooop/test_loop_engine.cpp`: one snapping case at a finer grid
  (e.g. 32) confirming size/position quantize to the smaller segments.
- User-run GUI checklist: knob reaches the new positions on both panels,
  menus show six entries, and an eyeball on the 64-division display — 63
  bars will be dense on the MetaModule screen.

## Docs

- `Loooop.md` Grid bullet: "Off (the default), 4, 8, 16, 32, or 64".
- `panel-specs/loooop.yaml` comment: "4-position snap knob" → "6-position".
