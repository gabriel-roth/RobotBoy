# SDK 2.3 / OOM handling — user checklist

Automated tests, both builds, and the headless-simulator A/B all pass. What's left needs the actual hardware, because neither the exception bridge nor a real out-of-memory condition exists off-device: the simulator builds RobotBoy as a built-in (no plugin loader, no plugin arena) and the host has gigabytes of RAM.

**Prerequisite: the MetaModule must be on firmware v2.3.0 or later.** This build will be refused outright by v2.2 and earlier — `Version::can_host_version` requires the firmware's SDK minor to be >= the plugin's.

## Loading

- [ ] The plugin loads at all on fw 2.3. (If it doesn't, the console will say the SDK version is too new — that means the firmware isn't actually 2.3.)
- [ ] All eight modules still appear in the browser and open in a patch: Loooop, Löp, MF-20, Onbetap, Particules, Ondes, Vespid, Retours.
- [ ] Load a few of the `mm-test-patches/` patches and confirm nothing has regressed audibly.

## The graceful-OOM path (the point of the change)

Each Loooop or Löp reserves ~23 MB at 48 kHz, out of ~290 MB shared by the whole patch.

- [ ] Fill a patch with Loooops until one won't fit. Adding it should show **"Not enough memory to load module"** and leave the patch playing. Before this change it would have taken the patch (or the device) down.
- [ ] The patch stays usable afterwards — the failed module simply isn't added, and you can keep editing.

## The sample-rate degrade path

This is the path that used to reach `std::terminate`. At 96 kHz the buffer doubles to ~46 MB.

- [ ] With a **fresh, empty** Loooop in a busy patch, switch the sample rate 48 kHz → 96 kHz. It must not crash.
- [ ] If memory was too tight to grow the buffer, a notification appears reading roughly **"Loooop: not enough memory at this sample rate. Max loop time now 30.0 sec"** — plain ASCII, no boxes or garbled characters.
- [ ] Recording after that notification works and stops at the stated shorter length rather than misbehaving.
- [ ] If there *was* enough memory, no notification appears and you get the full 60 s. (Notification only on genuine shortfall.)
- [ ] Switch back to 48 kHz and confirm the looper returns to normal.
- [ ] Repeat with Löp — the message should say "Lop:" (ASCII, no umlaut).

## Non-regression

- [ ] A Loooop with **audio already recorded** survives a sample-rate change the way it always did: loop preserved, played back repitched, no reallocation.
- [ ] Particules and Retours are untouched by this work — spot-check one patch of each.
